# 校内BBS论坛系统设计文档

## 1. 系统架构

系统采用经典的前后端一体化 Spring Boot 架构，整体分为以下层次：

- 表现层：Thymeleaf 页面、REST Controller
- 业务层：Service 接口与实现类
- 数据访问层：MyBatis-Plus Mapper + XML
- 基础支撑层：JWT、Redis、全局异常处理、AOP、拦截器
- 数据层：MySQL 8.0

## 2. 技术架构说明

| 层次 | 技术 |
|------|------|
| 后端框架 | Spring Boot 2.7.18 |
| ORM | MyBatis-Plus 3.5.7 |
| 前端模板 | Thymeleaf |
| 数据库 | MySQL 8.0 |
| 缓存 | Redis |
| 认证 | JWT + Spring Security BCrypt |
| 富文本安全 | Jsoup |
| 接口文档 | SpringDoc OpenAPI |
| 样式框架 | Bootstrap 5 |

## 3. 模块设计

### 3.1 用户模块

- 用户注册、登录、个人资料维护
- 管理员审核用户状态
- 支持角色区分：普通用户、管理员

### 3.2 板块模块

- 板块展示与筛选
- 管理员维护板块状态
- 板块下帖子数量统计

### 3.3 帖子模块

- 发帖、编辑、删除
- 首页帖子列表与板块帖子列表
- 帖子详情与回复树
- 管理员置顶、加精、违规下架、恢复正常

### 3.4 回复模块

- 一级回复与楼中楼回复
- 回复楼层展示
- 回复树结构构建

### 3.5 需求悬赏模块

- 悬赏创建、采纳、积分冻结与释放
- 悬赏状态流转

### 3.6 管理模块

- 用户审核
- 帖子管理
- 操作日志记录

## 4. 分层设计

### 4.1 Controller 层

负责处理请求参数、鉴权信息和响应结构。主要控制器包括：

- `AuthController`
- `UserController`
- `BoardController`
- `PostController`
- `ReplyController`
- `DemandController`
- `AdminUserController`
- `AdminPostController`
- `AdminBoardController`

### 4.2 Service 层

负责具体业务逻辑，例如：

- 帖子创建时板块帖子数增加
- 帖子删除时板块帖子数减少
- 浏览帖子时浏览量自增
- 悬赏积分冻结与结算
- 回复树构建

### 4.3 Mapper 层

负责数据库访问，采用 MyBatis-Plus 和 XML 自定义查询结合的方式。

### 4.4 实体与 VO 层

- `entity`：数据库实体
- `dto`：请求传输对象
- `vo`：页面展示对象

## 5. 核心业务流程设计

### 5.1 登录认证流程

1. 用户提交用户名和密码
2. 系统校验密码并签发JWT
3. 前端存储token
4. 请求接口时通过拦截器解析token
5. 将当前用户ID和角色写入请求属性

### 5.2 发帖流程

1. 用户选择板块
2. 输入标题与富文本内容
3. 系统清洗HTML内容
4. 保存帖子数据
5. 板块帖子数 +1

### 5.3 帖子详情流程

1. 请求帖子详情
2. 校验帖子是否存在、是否删除、是否违规下架
3. 浏览量 +1
4. 查询作者信息、板块信息、回复列表
5. 组装详情VO返回

### 5.4 管理员违规下架流程

1. 管理员在后台帖子列表点击“违规下架”
2. 接口将帖子 `status` 更新为 `2`
3. 前台详情接口拒绝展示该帖子
4. 后台列表显示“恢复正常”按钮

## 6. 安全设计

### 6.1 身份认证

采用JWT无状态认证，减少服务端会话依赖。

### 6.2 权限控制

- 普通用户仅能操作自己的内容
- 管理员可执行后台管理接口
- 通过 `RequireRole` 注解和拦截器属性共同控制权限

### 6.3 XSS 防护

- 发帖内容通过 Jsoup 清洗
- 移除 script、iframe 等危险标签
- 删除事件属性和 javascript 伪协议链接

### 6.4 逻辑删除

- 用户、帖子、回复等采用 deleted 字段控制逻辑删除
- 避免物理删除导致的业务关系丢失

## 7. 部署结构

- 应用服务运行在 8080 端口
- 数据库连接 MySQL `bbs` 库
- Redis 作为缓存和扩展能力预留
- 上传文件默认存储在应用运行目录下的 `upload/`

## 8. 总结

本系统采用清晰的分层设计与模块化组织方式，满足课程设计和实际演示需要，具备较好的可维护性与扩展性。
